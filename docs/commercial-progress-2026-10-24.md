# 商业化推进：2026-10-24

## 本轮发现与改动

- 线上首页前 30 件商品均无公开价格预览，近期入库顺序掩盖了现有报价价值。
- 只读盘点：97,689 件商品、227,073 条历史报价，其中 97,673 条在近 30 天内；50 条启用的合作链接。这些是采集和配置数量，不代表成交、活跃用户或实时库存。
- 原发现排序 RPC 公开调用约 3 秒后超时。改为先限定近期有报价商品，再筛选、排序窄行，最后加载完整商品资料。保留现有互动权重和药妆关键词范围，不按佣金排序。
- 生产公开 RPC 回读成功，一次实测 520ms；首页前 30 件均有公开价格概览，前后两页无重复。单次时延不构成性能 SLA。
- 首页接回发现排序；输入关键词仍搜索完整目录，排序接口失败时回退到完整目录。
- 匿名概览支持价格排序和预算筛选；概览不计入已查询清单合计，不消耗查询额度。
- 搜索词进入 `q` 参数，复制链接和刷新可恢复搜索；旧分页结果不能混入新搜索。
- 区分价格预览失败与无报价，提供重试，并将操作状态移到价格内容上方。预算滑杆补齐读屏名称、无限预算说明及触摸区域。
- 首次部署后的严格线上检查发现排序在公开请求下仍可能超时并回退。补充公开报价覆盖索引后，查询计划使用 Index Only Scan、Heap Fetches=0；公开接口一次实测 340ms，线上浏览器验收通过。首次工作流的失败记录保留，不以本地测试代替线上验收。
- 第二次工作流依然捕获了偶发排序超时，因此不能只依赖索引或单次测速。最终将排序结果放入不可公开读取的 `private.catalog_discovery`，通过数据库 Cron 每 15 分钟并发刷新；公开 RPC 只读排序缓存，商品资料和公开价格仍走现有实时读取。刷新命令、匿名覆盖/分页检查、缓存权限与定时任务启用状态均已验证。一次数据库查询为 0.598ms、公开 HTTP 为 101ms；后续仍以真实线上工作流结果为准。
- 登录、注册与找回密码共用站内返回地址校验，拒绝外站、反斜杠与控制字符伪装。邮件回跳请求保留原商品页，已自动建立会话的注册直接继续原操作；过期验证链接给出明确提示。
- 依赖审计发现 9 项已知漏洞（含 1 项 critical），在原兼容范围内更新补丁后审计为 0。Astro 为 7.4.2、Vite 为 8.3.5；声明与 CI 统一使用 Node 24，以满足现有条码依赖和新框架的最低要求。审计为 0 不等同于整站已完成安全认证。
