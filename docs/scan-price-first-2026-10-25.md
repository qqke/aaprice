# 扫码优先录价与占位商品

- 扫码页提供“扫码后优先输入价格”开关，默认关闭，在当前浏览器记住选择。存储被禁用时仍能在当前页面使用该选择。
- 开启后扫到商品会携带 `record=1` 进入详情，自动展开价格记录，将价格字段放在表单首位并聚焦、滚动到输入位置。未登录时登录返回路径保留录价意图。浏览器是否自动弹出软键盘仍由设备规则决定。
- 快速录价模式不自动选中默认门店，可先保存个人价格；公共价格提交仍要求门店并经过审核。
- 登录用户扫描未收录条码时，通过受限 RPC 建立“待完善商品 · JAN …”占位记录。只接受条码，客户端提供的商品名称等资料不会直接发布；同一条码重复扫描复用商品与待办。未登录时保留条码，引导登录后登记。
- 占位记录进入既有管理员待审核列表，显示“完善资料”。管理员填入真实商品名称、按需补充品牌等信息并保存后，关闭对应待办；商品 ID 和条码保持不变，已录入个人价格继续关联原商品。
- 新增写入口仅允许已登录用户，管理员完善接口仍检查管理员身份。关闭原有公开商品表直接插入路径，保留既有私密记录与补录审核接口。登记设置每日上限，重复读取已有商品不受新建上限影响；不能将未完善占位记录直接审核通过。

验证：数据库迁移先在事务内预演并回滚，生产应用后再次执行 `supabase/checks/scanned_product_stubs.sql`。覆盖重复登记、不同用户扫描同一条码、私密价格关联、直接插入拒绝、非管理员拒绝、登记上限、真实名称校验、完善后保留价格和关闭待办。合成用户、商品、价格与待办全部回滚，未发送邮件。

前端使用拦截 API、合成相机和测试账号验证完整闭环，包括开关开/关、刷新保留、匿名登录跳转、价格框焦点与顺序、无门店个人价格保存、管理员填写并关闭待办。新增偏好存储单元测试。

Supabase Advisor 仍因连接权限拒绝运行；只读 SQL 审计确认新增函数安全搜索路径、公开执行和管理员匿名执行风险项为空。没有使用真实未知条码在生产创建测试占位商品，也没有实测手机软键盘或真人扫码。
