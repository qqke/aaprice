## 本轮发现与改动

- 线上首页前 30 件商品均无公开价格预览，近期入库顺序掩盖了现有报价价值。
- 只读盘点：97,689 件商品、227,073 条历史报价，其中 97,673 条在近 30 天内；50 条启用的合作链接。这些是采集和配置数量，不代表成交、活跃用户或实时库存。
- 原发现排序 RPC 公开调用约 3 秒后超时。改为先限定近期有报价商品，再筛选、排序窄行，最后加载完整商品资料。保留现有互动权重和药妆关键词范围，不按佣金排序。

- 匿名概览支持价格排序和预算筛选；概览不计入已查询清单合计，不消耗查询额度。
- 搜索词进入 `q` 参数，复制链接和刷新可恢复搜索；旧分页结果不能混入新搜索。
- 区分价格预览失败与无报价，提供重试，并将操作状态移到价格内容上方。预算滑杆补齐读屏名称、无限预算说明及触摸区域。
- 首次部署后的严格线上检查发现排序在公开请求下仍可能超时并回退。补充公开报价覆盖索引后，查询计划使用 Index Only Scan、Heap Fetches=0；公开接口一次实测 340ms，线上浏览器验收通过。首次工作流的失败记录保留，不以本地测试代替线上验收。
- 第二次工作流依然捕获了偶发排序超时，因此不能只依赖索引或单次测速。最终将排序结果放入不可公开读取的 `private.catalog_discovery`，通过数据库 Cron 每 15 分钟并发刷新；公开 RPC 只读排序缓存，商品资料和公开价格仍走现有实时读取。刷新命令、匿名覆盖/分页检查、缓存权限与定时任务启用状态均已验证。一次数据库查询为 0.598ms、公开 HTTP 为 101ms；后续仍以真实线上工作流结果为准。
- 登录、注册与找回密码共用站内返回地址校验，拒绝外站、反斜杠与控制字符伪装。邮件回跳请求保留原商品页，已自动建立会话的注册直接继续原操作；过期验证链接给出明确提示。
- 依赖审计发现 9 项已知漏洞（含 1 项 critical），在原兼容范围内更新补丁后审计为 0。Astro 为 7.4.2、Vite 为 8.3.5；声明与 CI 统一使用 Node 24，以满足现有条码依赖和新框架的最低要求。审计为 0 不等同于整站已完成安全认证。

- 后台点击率仅统计同一会话、入口来源与合作链接在曝光后的点击，两者均须落在所选时间窗内；无有效曝光时显示 —。旧事件不删除也不混入新口径；需积累真实流量，浏览器拦截和请求失败可能漏记。
- 回归结果：211 项测试中 209 项通过、2 项跳过，生产构建与隔离浏览器检查通过。数据库以现有两个合作链接创建事务内测试事件，覆盖重复会话、来源/链接不匹配、先点击后曝光、过期及未来时间、旧埋点排除和管理员权限，全部回滚。迁移已应用，应用后同一事务检查再次通过。
- Supabase Advisor 工具因连接权限不足拒绝访问；改用仓库只读安全审计检查，未发现缺少 RLS 的公开表、缺少安全 search_path 的特权函数或授予 PUBLIC 的特权函数。另对本次管理 RPC 显式撤回匿名执行权限，并验证非管理员拒绝访问；这不是全库安全认证。

## 提醒与后台访问边界修正

- 生产核查发现提醒后台 RPC 对匿名和普通登录用户有显式执行权限，最近行为日志 RPC 缺少管理员校验。已撤回四个后台 RPC 的客户端权限、为日志接口补齐管理员校验，并撤回所有 admin_ RPC 的匿名执行权限。
- 根因之一是 public schema 中 `postgres` 新函数的默认 ACL 显式授权客户端，单独 revoke PUBLIC 不足以收紧。已取消该默认授权，审计新增对应检查；应用后匿名管理函数、客户端后台函数和迁移默认客户端授权均为 0。
- 领取提醒时重新检查启用状态、当前目标价、收件邮箱确认和提醒归属。个人页明确邮箱渠道、相同或更高价格不重复提醒，以及停用对已进入发送流程邮件的限制。
- 212 项测试中 210 项通过、2 项跳过，生产构建通过。生产数据库事务回归覆盖合格/停用/降低目标/未确认邮箱、领取租约、后台角色权限、普通用户拒绝及管理员成功访问；测试全部回滚，没有发送邮件。五个匿名 HTTP 接口检查均返回 401。
- 本轮发现并修复的是实际访问边界问题。当前没有足够日志证据判断历史是否曾被他人访问，不能宣称没有发生过越权访问；此前只检查 PUBLIC 授权的审计不足以覆盖显式 anon/authenticated 授权。

## 地理信息与合作商品复核

- 报价映射曾把空坐标和空距离转为 0，可能产生虚假的 0 米或 `0,0` 地图链接。现在保留未知值，越界坐标与负距离同样不进入定位；缺坐标时地图使用门店名称和地址。无效、空或非正报价不会成为免费商品。
- 详情页最近门店推荐复用现有实体门店选择函数，排除在线商店；门店选择排序不再把空坐标转换为 0。缓存定位改为首页挂载后恢复，修复定位用户返回首页时的 SSR 水合不一致。
- 直接目标页检查首次 50/50 返回 200，但元数据复查发现 HTTP 成功不能证明商品一致或可购买。先停用并逐项替换 4 条售罄、JAN 不符或规格/商品状态疑点，详情见联盟上线流程；更新后生产覆盖回读为 50 件、近期有价 43 件、首页前 30 件带入口 14 件。没有访问联盟追踪链接、创建点击或订单。
- 生成器现在验证页面内精确 JAN、允许购买和非售罄状态，排除瑕疵品、中古和 Outlet；未知模板交由人工审核，并正确解码 EUC-JP。校验不再请求联盟追踪网址，避免验收制造点击。元数据检查仍不能代替人工核对规格、组合、运费和库存。
- 新增回归覆盖未知坐标/真实零距离、地图地址回退、最近实体店选择、定位缓存水合、不同字符编码、售罄候选跳过与生成器无联盟网络请求；不调用真实相机或定位授权，不写公共报价。

## 全目录门店搜索与加载修正

- 生产库有 23,688 家门店，23,677 家带坐标；个人页原先只在预载前 500 家里搜索，商品详情则在登录后并行请求 50 页、最多 25,000 家门店。现在采用数据库端全目录搜索与全局距离排序，结果每次最多展示 100 家，并明确提示补充关键词缩小范围；后台原有 500 条读取上限保持兼容。
- 新函数为 `SECURITY INVOKER`，使用调用者现有 RLS 权限，只读公开门店资料。按名称、连锁、城市、县和地址查询，支持全半角规范化及既有スギ名称别名；百分号、下划线与标点按字面搜索。实体门店过滤发生在排序与限额之前，空坐标不会被当作距离零。
- 两个记录页共用防抖搜索：过期响应不能覆盖新关键词，加载与失败状态明确、可重试；搜索框回车不会提交价格。切换搜索后保留已选门店；收藏、进行中任务与指定门店按 ID 补齐资料，分批读取，不再依赖默认候选范围。指定的在线门店或不可用门店不会伪装成实体门店选择。
- 迁移前后均使用匿名角色验证前 500 家之外的门店可找到、全库最近距离、全半角搜索、分页无重复、字面标点、限额和坐标参数边界。公开 HTTP 复验找到 `vdrug-01769`（Ｖ・drug 岩村店），附近前 100 家的距离顺序通过独立计算核对。一次首次 HTTP 为 4,755ms，随后附近查询 228ms；不将单次数据作为 SLA。
- 只读安全审计未发现新增特权函数风险；Supabase Advisor 工具仍因连接权限拒绝执行，已记录其范围限制。数据库没有添加或改写门店、价格、奖励与点击数据。
- `npm test` 为 218 项：216 项通过、2 项跳过；构建与隔离浏览器回归通过，覆盖旧响应隔离、失败重试、已选门店保留、收藏/任务名称补齐、指定在线门店拒绝、回车不提交价格及原有完整导出流程。

## 缺失商品补录衔接

- 线上已部署的门店选择界面使用隔离会话、实际公开门店 RPC 复验，成功选择 `vdrug-01769`；没有访问真实私有账户数据或保存价格。
- 个人页“去补录商品”的 JAN 正则被多转义，导致条码跳转丢失。已修复，符合现有 8 位或 12–14 位长度的纯数字输入会带入 `/scan/?jan=...`。
- 乐天补录预填原先在没有匹配 JAN 的链接时使用第一条搜索结果，可能把其他商品写入草稿。现在仅接受链接路径中的精确 JAN 或明确匹配的 variantId，不把推荐商品冒充目标商品。
- 隔离浏览器从个人页查询未登记 JAN、打开补录入口并检查草稿条码；外部查询被拦截为失败/无关商品响应，确认名称保持空白且未提交审核。单元测试覆盖无关结果拒绝、精确商品路径、匹配 SKU 与 HTML 转义参数。
- 当前 `npm test` 共 219 项：217 项通过、2 项跳过，构建及隔离浏览器回归通过；未发送额外邮件、创建公共价格或奖励。

## 贡献审核与积分闭环

- 生产审核函数此前只发布报价，没有兑现页面承诺的贡献积分。现在管理员通过待审公开贡献时，在同一事务发布报价、按 `approved_contribution_reward` 发放积分，并完成该贡献者认领、商品与门店匹配的任务；其他用户的任务不受影响。
- 保留行锁和待审状态校验，以既有贡献奖励唯一索引防止重复发奖。驳回与私密记录不会获得奖励；不追溯补发历史积分，也未启用自动共识审核。
- 普通用户直接写日志表仅能创建、修改自己的私密记录，不能伪造待审/通过状态、把已审核记录重新排队或写入审核字段。公开贡献仍走既有鉴权 RPC，个人记录保存方式不变。
- `supabase/checks/contribution_review.sql` 使用真实数据库角色验证：私密隔离、直接伪造拒绝、普通用户审核拒绝、驳回不发奖、私密记录不能审核、通过发布与发奖、任务完成、重复审核拒绝、重提不重复发奖、其他贡献者任务保留。迁移前复现伪造漏洞，迁移事务预演与生产应用后检查均通过。合成账号、报价、任务、积分全部回滚，没有发送邮件。
- `npm test` 219 项：217 通过、2 跳过；构建通过。只读安全审计中的缺失 RLS、不安全特权函数搜索路径、公开特权执行、匿名管理员执行及客户端工作流执行风险项均为空。Supabase Advisor 仍因连接权限拒绝运行，未将 SQL 审计等同于完整 Advisor 检查。
